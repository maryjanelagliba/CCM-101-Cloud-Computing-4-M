# Mission Reflection

## 1. Which cloud infrastructure component do you think is the most important? Why?

For me, storage resources are one of the most important components of cloud infrastructure because they are responsible for keeping important data and files available. Applications need storage to save information, configurations, databases, and other resources that users depend on. Without reliable storage, even a powerful cloud system would have difficulty maintaining the information needed by its applications.

## 2. How does Linux support cloud computing?

Linux supports cloud computing by providing a reliable operating system for managing servers and cloud workloads. It offers useful command-line tools that allow engineers to check hardware resources, monitor processes, manage storage, and configure network settings. Because Linux is flexible and widely supported, it is commonly used for virtual machines, servers, and containers in cloud environments.

## 3. Why is technical documentation important before deploying infrastructure?

Technical documentation is important because it gives engineers a clear record of the planned infrastructure and its configuration. It helps teams understand how each component works together and allows them to identify possible issues before deployment. Proper documentation can also make future troubleshooting, maintenance, and upgrades easier.

## 4. What new skills did you learn during this laboratory activity?

I learned how to use Linux terminal commands to examine the resources of a cloud-based server. I was able to practice checking information such as the operating system, CPU, memory, storage, hostname, and network configuration. I also improved my ability to organize technical information using Markdown and learned how different cloud providers offer similar infrastructure services.

## 5. How has your GitHub portfolio improved after completing this mission?

My GitHub portfolio has become more organized because I added a separate laboratory folder with different technical documentation files. I learned how to arrange reports, cloud provider comparisons, infrastructure information, and other project materials in a structured repository. This activity also helped me become more familiar with committing changes and maintaining documentation that can be useful for future cloud computing projects.
